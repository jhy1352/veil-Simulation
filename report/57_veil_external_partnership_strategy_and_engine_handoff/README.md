## 1. Current strategic position

VEIL is not to be presented as a finished commercial product. The accurate position is:

- Core engine architecture has been substantially implemented.
- The project is in a late-stage engineering / red-team / hardening phase, not a completed product-release phase.
- The engine itself is considered something the solo creator can continue to complete.
- A separate post-engine research problem has emerged: improving narrative quality and human-like creative novelty at a scale that is difficult to execute alone.
- The proposed solution is not primarily hiring conventional narrative staff. The intended research direction is large-scale AI-assisted analysis of human literary/narrative history to extract recurring narrative structures and mechanisms, then test their usefulness inside VEIL.
- This research direction is a hypothesis and must not be presented as already proven.

Recommended external framing:

> VEIL's core simulation engine is being completed independently through late-stage red-team validation. The remaining narrative challenge is a separate research problem: using AI to analyze large bodies of human narrative history, extract reusable structural mechanisms, and test whether they can improve the quality and diversity of AI-generated interactive narratives.

Avoid:

- "VEIL is almost a finished product".
- "The human narrative system is already proven".
- "VEIL has patented IP" unless patent status is independently verified.
- "I need engineers because I cannot finish the engine."

Prefer:

- "The core engine is being completed independently."
- "The next research problem has become too large for a single-person experimental workload."
- "I am looking for a research/technology partner for the narrative-quality phase."

## 7. Complete VEIL engine handoff/problem state

The following are the known unresolved or unproven items at the reference state. They are not all equal in severity.

### P0 — local storage / persistence integrity

FACT:

- The client persistence payload can grow with character, worldInfo, messages, engineState, history, diagnostics, novelHistory, passports, traces, latency, checkpoints, pendingCandidates, and related data.
- Save failure can currently be treated as a warning rather than a hard integrity boundary.

Risk:

- In-memory canonical world can continue while durable browser storage remains stale.
- A later refresh can restore an older state.

Classification: RED / P0 structural reliability risk.

### P1 — Passport projection scaling

FACT:

- Passport projection can repeatedly scan/sort historical records.

Risk:

- Cost grows with history size.

Classification: YELLOW/RED depending runtime scale; structural scaling issue, not core authority corruption.

### P1/P2 — historical scans

FACT:

- Identity/novel/inventory validation paths can repeatedly scan historicalRecords.

Risk:

- Long campaigns may become increasingly expensive.

Classification: YELLOW; benchmark required for exact threshold.

### P1 — Narrative Authority Gap

FACT:

- Commit-first flow prevents a failed canonical commit from being presented as a successful state mutation.
- However, after successful commit, raw Phase 2 narrative text is not deterministically re-validated as a complete factual claim set against the committed state.
- Fallback non-mutation narrative similarly lacks a deterministic claim gate.

Risk:

- Canonical state can remain correct while narrative text can still contain unsupported factual claims.

Classification: YELLOW/RED depending product promise. If the promise is strict narrative truthfulness, this must be closed.

### P1 — Context continuity

FACT:

- App sends previous messages to `/api/chat`.
- Server uses `messages.slice(-20)`.
- Canonical context is not guaranteed to be present in every request.

Risk:

- Long play can cause the model's literal context window to begin with prior assistant narrative rather than canonical state/context.
- The model can therefore lose direct access to critical state unless it is re-injected deterministically.

Classification: RED for long-term narrative continuity until hardened.

### Candidate maximum-count issue

FACT:

- `parseCandidatesBlock()` currently slices the raw candidate list to five before a later `candidates.length > 5` check.

Risk:

- A model outputting seven candidates may silently become five before the overflow check can observe the violation.

Classification: YELLOW; contract-enforcement defect.

### originInputId residual fallback

FACT:

- `buildSafeProposalFromCandidate()` has an `originInputId || candidate.candidateId` fallback.

Risk:

- If the caller omits `originInputId`, provenance can collapse input identity into candidate identity.

Classification: YELLOW; provenance hardening required.

### Recovery / Triage integration

FACT:

- Recovery semantics were defined to repair grammar/format/interpretation without inventing meaning.
- EOF unterminated-string auto-close was rejected as unsafe.
- Candidate-level failure should remove only that candidate.
- Triage is conceptually distinct from Recovery.
- Static evidence previously found no proven direct runtime call from the actual LLM path into `diagnoseForRecovery()` / Triage behavior.

Classification: UNKNOWN until current code is re-audited after any subsequent changes.

### Causal compiler runtime integration

FACT from prior audit:

- `causalCompiler.ts` exists.
- `server.ts` previously showed no direct import/use of it.
- `parseNaturalLanguageToEvents()` is pattern-based rather than a general causal compiler.
- Event IDs in that path used `Date.now()` despite deterministic naming.
- `src/engine/language/index.ts` did not export causalCompiler in the audited state.

Classification: UNKNOWN until current branch code is re-audited.

Important invariant:

- Do NOT weaken the causal validator merely to make normal actions pass.
- Missing an explicit natural-language cause must not automatically mean DENY if a valid causal path can be deterministically derived and grounded in Canonical State/History/World Rules.
- A natural-language cause label alone is not proof.

### runtimeProjection restrictions

FACT from prior audit:

- runtimeProjection blocks actions whose causal dependency is CLAIM, HEARSAY, UNPROVEN, NEGATED, INTENTIONAL, POSSIBLE, COUNTERFACTUAL, HYPOTHETICAL, or UNVERIFIED.

This remains a strict authority boundary and should not be casually weakened.

## 8. Strong engine areas already established

The audited architecture has strong structural foundations:

- One sovereign mutation path through `SovereignEngine.submitProposal()`.
- Candidate → Identity Resolution → MeaningTree → Proposal → PreAuth → Sovereign Commit → Canonical State → Immutable History.
- `stateVersion`, `requestId`, `eventId`, `previousStateHash`.
- Deterministic replay and hydration checks.
- Identity Resolver statuses EXACT / RECOVERED / NOVEL / AMBIGUOUS / CONFLICT.
- Index miss is not treated as Novel.
- Novel/CANON lifecycle preserves lineage.
- Passport is a projection, not authority.
- Server PreAuth is not the final commit; App performs the sovereign commit.
- Commit failure results in no canonical mutation and no successful narrative display in the corrected Commit-First flow.
- Inventory acquisition validation uses causal authority, verified event identity, duplicate-event protection, item relevance, and provenance constraints.

These strengths should be preserved while fixing the remaining reliability/integration issues.

## 10. Human Narrative Prior boundary

This is a separate research workstream and must not be confused with engine completion.

Its proposed pipeline is:

Human narrative corpus → AI-assisted structural analysis → recurring structure/mechanism extraction → generalization → current VEIL world/person/relationship/history/causal state → novel concrete instantiation → final narrative

Key principle:

- Human Narrative Prior is a creative prior / choice-space, not truth authority.
- It must not directly dictate canonical state.
- Its actual effect on narrative quality is UNKNOWN until experimentally validated.

The research target is not to copy plots. It is to identify durable human narrative structures and mechanisms, while preserving variation/detail layers.
