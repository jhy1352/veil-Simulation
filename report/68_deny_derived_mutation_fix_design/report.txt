Report 68 — DENY-Derived Canonical Mutation Fix Design

FACTS
1. Current proposalParser.ts unconditionally converts candidate.chapterChanges into ADVANCE_CHAPTER.
2. Current server.ts passes the resulting proposal into EngineValidator.
3. EngineValidator explicitly rejects empty proposals.
4. Report 67 DENY raw evidence showed chapter-only mutation surviving PreAuth and commit.

FIX SCOPE
- Treat chapterChanges as NON-CANONICAL roadmap metadata unless the candidate carries an explicit semantic intent event whose action is ADVANCE_CHAPTER and whose scope/modality indicate player intent.
- Do not use keyword matching against prose.
- Removing unsupported mutation leaves narrative generation intact.
- An emptied proposal is rejected by EngineValidator, causing the existing server-side non-mutation literary fallback.

LIMITATION
This patch establishes a conservative semantic-intent binding for chapter advancement. It does not claim complete player-intent binding for every mutation type; that requires a separately sourced player-intent semantic representation.

REGRESSION TARGET
DENY case: candidate with chapterChanges but no qualifying player-intent semantic event => proposal actions [] => PreAuth REJECT => no commit/stateVersion change => non-mutation fallback.
