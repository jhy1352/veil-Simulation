# 추후 런타임시 해당 문제 발견 시 보라

## 목적
`semanticEvents` 관련 Candidate 소실 의심 사항을 현재 단계에서 선제 수정하지 않고, 향후 실제 런타임 테스트에서 동일 현상이 재현될 경우 이 기록을 기준으로 재포렌식한다.

## 현재 판단

- **FACT:** `semanticEvents`는 Candidate의 의미를 엔진이 읽을 수 있는 핵심 입력이며, 현재 Semantic Translation 경로에서 사용된다.
- **FACT:** 현재 코드의 `getCandidateSemanticEvents()` 계열 처리에서는 semanticEvents가 없거나 유효하지 않은 경우 빈 배열(`[]`)로 축약될 수 있는 지점이 있다.
- **UNKNOWN:** 과거 런타임에서 실제로 몇 개의 Candidate가 `semanticEvents` 부재/빈 값 때문에 소실되었는지는 현재 확보된 증거만으로 입증되지 않았다.
- **UNKNOWN:** semanticEvents가 LLM 출력 단계에서 없었던 것인지, 파싱/어댑터 단계에서 소실된 것인지, 검증 과정에서 무효화된 것인지, 후단에서 `[]`로 축약된 것인지 원인은 아직 확정되지 않았다.

## 런타임에서 재발견되면 확인할 것

반드시 Candidate 하나의 `eventId`/식별자를 따라 다음 단계별 원본과 상태를 비교한다.

`LLM raw semanticEvents`
→ `CandidatePacket.semanticEvents`
→ `getCandidateSemanticEvents()`
→ `CausalCompiler`
→ `MeaningTree`
→ `StateTransitionProposal`
→ `PreAuth`
→ `Commit`

각 단계에서 최소한 다음 상태를 구분한다.

- `PRESENT`
- `ABSENT`
- `INVALID`
- `EMPTY`
- `DROPPED`

`[]` 하나만 남고 원인이 사라지는 경우를 특히 의심한다.

## 중요 불변조건

1. **semanticEvents가 없다고 Recovery가 의미를 추론해서는 안 된다.**
2. 구조적으로 복구 가능한 문법/JSON 손상만 Recovery 대상으로 한다.
3. Candidate N의 실패가 Candidate M의 소실로 이어져서는 안 된다.
4. 격리/Quarantine된 Candidate는 원본 payload와 실패 이유를 보존해야 한다.
5. `Candidate invalid`와 `semantic invalid`를 동일한 실패로 취급하지 않는다.
6. `ABSENT / INVALID / EMPTY`를 원인 없이 `[]`로 합치지 않는다.
7. Phase 2가 새로운 의미를 만들어내어 Phase 1 Candidate의 탈락을 복구하는 구조로 바꾸지 않는다.
8. 최종 canonical truth는 계속 Engine의 commit gate가 담당한다.

## 권장 런타임 계수

- INPUT_COUNT
- PARSED_COUNT
- RECOVERY_PASSED_COUNT
- RECOVERY_QUARANTINED_COUNT
- SEMANTIC_PRESENT_COUNT
- SEMANTIC_INVALID_COUNT
- SEMANTIC_ABSENT_COUNT
- SEMANTIC_EMPTY_COUNT
- CAUSAL_ACCEPTED_COUNT
- CAUSAL_REJECTED_COUNT
- DIVERSITY_ACCEPTED_COUNT
- PREAUTH_ALLOWED_COUNT
- PHASE2_SELECTED_COUNT
- COMMIT_COUNT

## 수정 시점

현재는 이 문제만을 근거로 핵심 파이프라인을 선제적으로 뜯어고치지 않는다.

향후 실제 런타임에서 `semanticEvents` 때문에 Candidate가 사라지는 현상이 재현되면:

1. 재현 런타임의 raw evidence를 먼저 보존한다.
2. 동일 Candidate의 eventId lineage를 EOF까지 추적한다.
3. 실제 소실 단계와 소실 원인을 확정한다.
4. 원인이 확인된 지점만 최소 수정한다.
5. 수정 후 동일 공격/정상 입력을 다시 런타임 테스트한다.

**현재 상태: WATCHLIST / 미해결 이슈로 기록. 실제 Candidate 소실은 아직 입증되지 않음.**
