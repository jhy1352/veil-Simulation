# 다음 참모 인수인계 프롬프트

너는 VEIL / TRPG 3.1의 다음 기술 참모다.

## 현재 임무
사용자는 이제 **파이프라인 통합 및 최적화**라는 큰 작업을 시작하려 한다.
현재 작업 브랜치는:
`work/pipeline-prune-from-ea8ca300`

가장 먼저 해야 할 일은 코드를 수정하는 것이 아니라 **현재 branch의 실제 runtime call graph를 forensic하게 고정하는 것**이다.

## 사용자의 절대 기준
- 코드/실제 runtime evidence > report > AI/Studio 주장
- FACT / INFERENCE / HYPOTHESIS / UNKNOWN을 명확히 구분
- RED / YELLOW / GREEN / UNKNOWN은 증거 수준에 따라 판정
- `verified`, `PASS`, `implemented`라는 문구를 증거로 취급하지 말 것
- 증거가 없으면 반드시 '입증되지 않음'이라고 할 것
- 관련 없는 리팩터링 금지
- 삭제 전에 실제 call-site와 runtime reachability 확인
- canonical authority는 SovereignEngine/commit gate에만 존재해야 함

## 핵심 forensic 사실
### Triage
현재 `src/engine/language/triageModule.ts`는 확인된 구현상:
- TRIAGE_STAMP 처리
- Candidates block 추출
- rawResponseText/rawCandidatesBlock 반환
- Recovery로 구조복구 책임 위임
정도가 중심이다.

Triage가 CausalCompiler, MeaningTree, history 기반 의미복구, canonical 판결 등을 한다고 가정하지 마라.

### Recovery
구조/JSON 복구 계층이다.
의미를 발명하면 안 된다.
특히 action, role, identity, epistemicStatus, polarity, cause, provenance, semanticEvents를 prose/history에서 임의 추론하면 안 된다.

### Semantic Translation
Candidate의 semanticEvents를 읽고 CausalCompiler → MeaningTree → Runtime Bridge → Proposal로 연결되는 핵심 의미 변환 계층이다.

### PreAuth / Commit
Canonical state mutation은 SovereignEngine의 commit 경계에서만 가능해야 한다.

### Phase2
최근 실제 runtime에서 `selectedCandidateId: null`인데도 Phase2가 QUERY/CLAIM/OBSERVED 형태의 semantic-looking 구조화 출력을 생성한 증거가 있다.
이것은 canonical mutation 자체를 증명하지는 않지만 **YELLOW**다.
Phase2는 narrative-only여야 하며 rejected Candidate를 복구하거나 canonical 의미를 재창조하면 안 된다.

## semanticEvents watchlist
현재 semanticEvents는 별도 watchlist 상태다.
`getCandidateSemanticEvents()`가 missing/invalid를 `[]`로 collapse할 수 있는 경로가 의심되지만, 실제 historical Candidate loss는 아직 입증되지 않았다.

런타임 재현 시:
```text
LLM raw semanticEvents
→ CandidatePacket
→ getCandidateSemanticEvents()
→ CausalCompiler
→ MeaningTree
→ Proposal
→ PreAuth
→ Commit
```
각 단계에서 PRESENT / ABSENT / INVALID / EMPTY / DROPPED를 구분하라.
Recovery에서 의미를 복원하지 마라.

## prompt leakage watchlist
P0-3에서 explanatory/example leakage 일부는 제거되었다.
그러나 live system instruction에 normative schema vocabulary가 남아 있다.
`PICKUP`, `GIFT`, `SUBJECT`, `TARGET`, `OBJECT` 등이 있다는 이유만으로 leakage라고 판정하지 마라.

과거 TRIAGE_STAMP가 Phase1 evidence에 등장한 원인은 아직 완전히 입증되지 않았다.
'이전 curl/context를 Gemini가 echo했다'는 설명은 INFERENCE 수준이다.
실제 Phase1 model input 전체를 확보해서 first occurrence를 추적해야 한다.
