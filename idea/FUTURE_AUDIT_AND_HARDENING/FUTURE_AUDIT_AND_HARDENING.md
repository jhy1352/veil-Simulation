# TRPG 3.1 — 과잉거부(Over-Rejection) 및 표현력 손실 방어 후속 감사

현재 Sovereign Engine의 주권·인과성 검증이 강화됨에 따라, 반대 방향의 결함인 **과잉거부(Over-Rejection)** 가능성을 후속 감사 대상으로 지정한다.

## 감사 목적

엔진이 세계관의 주권과 개연성을 보호하는 과정에서, **실제로 허용되어야 할 정상적인 플레이어 행동이나 LLM 창작까지 부당하게 거부하지 않는지** 검증한다.

특히 다음 원칙을 유지한다.

> **강한 검증은 목적이 아니라 수단이다.**
> 세계의 규칙을 지키되, 세계 안에서 가능한 행동과 창작의 자유까지 불필요하게 억압해서는 안 된다.

## 주요 감사 대상

1. **정상적인 창작의 과잉거부**

   * 새로운 NPC, 장소, 사건, 아이템 등의 창작이 정상적인 인과관계를 갖추었음에도 거부되는지 확인.
   * 기존 Canonical State에 없는 것이라는 이유만으로 무조건 차단하지 않는지 확인.

2. **행동 결과와 세계 규칙의 혼동**

   * 플레이어의 행동 자체를 거부해야 하는 경우와,
   * 행동은 허용하되 세계의 결과로 실패시키거나 예상 밖의 결과를 발생시켜야 하는 경우를 구분하는지 확인.

3. **인과성 Gate의 과잉 적용**

   * RESOURCE_EXCHANGE처럼 명확한 증명이 필요한 영역과,
   * 세계 내부에서 자연스럽게 발생할 수 있는 창작·발견·사건 발생까지 동일한 수준의 증명을 요구하지 않는지 확인.

4. **Action ACL의 과잉 제한**

   * LLM이 수행할 수 있는 창작 제안과 엔진만 수행해야 하는 상태 변경을 정확히 구분한다.
   * 단순히 위험 가능성이 있다는 이유만으로 LLM의 정상적인 제안 영역을 축소하지 않는다.

5. **정상적인 복합 행동**

   * 하나의 Proposal 안에서 여러 정상적인 행동이 결합될 때 불필요하게 Reject되는지 확인.
   * 액션 순서, 분할 처리, 신규 생성과 기존 상태 변경의 조합 등 정상적인 표현력을 검증한다.

6. **Defense in Depth의 부작용**

   * Parser → Validator → Commit 단계에 동일한 제한이 중복 적용되어 정상 Proposal이 불필요하게 차단되는지 확인.
   * 각 계층의 검증 목적과 책임이 중복되지 않는지 검토한다.

## 판정 원칙

취약점을 찾기 위해 무조건 RED를 부여하지 않는다.

* **실제 세계 규칙 위반을 막는 정당한 거부** → PASS
* **정상적인 세계 내부 행동을 막는 거부** → 과잉거부 취약점
* **행동은 허용해야 하지만 결과가 세계 규칙에 의해 제한되어야 하는 경우** → Fizzle/세계 반응과 Reject를 구분
* **근거가 부족하다는 이유만으로 창작 가능 영역까지 차단하는 경우** → 표현력 손실 위험

최종 목표는 **“무조건 거부하는 단단한 엔진”이 아니라, 가능한 것은 최대한 자유롭게 허용하면서 불가능한 것만 정확하게 거부하는 Sovereign Engine**이다.

## 향후 추가 작업

* **Candidate 상태변화 공통 게이트:** Candidate→Action 변환 후 실제 Canonical State 변화를 결정론적으로 판정하는 공통 경계를 설계·검증한다.
* **헌법 개정 검토:** 현행 철학과 `jhy1352/preview`의 1차 개정안을 비교·대조하여 철학과 충돌하는 개정사항을 식별한 뒤 최종 헌법 개정을 수행한다.
